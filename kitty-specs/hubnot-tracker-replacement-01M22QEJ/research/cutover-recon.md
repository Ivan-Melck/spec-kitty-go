`internal/helpercmd/production.go:99` explicitly supplies unavailable readiness and decomposition providers, and unavailable integration Git, for the M2 host. `internal/productionruntime` already accepts typed readiness/decomposition ports and effect dispatch providers, but does not itself admit an external tracker. Thus a complete *provider cutover* can deliver a reachable, bounded provider command family (inspect/read/write/export under the native product entry, with explicit binding and separate tracker-only semantics) and the successor real-provider qualification now, while leaving full production mission execution/adoption to M3. If root chooses actual mission decomposition composition in this mission, it must explicitly own readiness, effect/outbox recovery, external-reference bindings and cross-provider capability gates; this is a larger M3 slice, not a mechanical adapter replacement. Do not make existing unavailable stubs silently “ready.”

A recommended mission boundary is: Hubnot is the only active qualified/default work/discussion provider; a real product CLI consumer exercises its supported work lifecycle; M2 authority and unavailable noncomposed mission actions remain truthful; M3 real agents + full Git/workspace/mission orchestration remains unfinished. ## Required semantic decisions before coding

- **Authority:** Hubnot issue status, assignees, comments, relations and signed actor facts remain observed work/discussion data. They never confer execution lease, review verdict, mission acceptance or integration publication authority. Hubnot proposal/review/runner/merge commands are outside this adapter’s allowed subprocess vocabulary.
- **Concurrency:** Hubnot expected heads reject a locally stale observation, and actor-ref publication uses CAS. Another actor can publish a concurrent head; there is no global issue CAS. Do not advertise `AssignmentAtomicClaim`, `CompensationConditional` or global guarded update based merely on `--expect`. Preserve explicit unsupported refusal for guarantees the neutral contract actually requires. Multihead reads must return conflict/ambiguous, never pick a winner.
- **Observation identity:** neutral `tracker.Revision` is uint64, while Hubnot has full event IDs and catalog snapshots. Define a deterministic opaque observation token plus exact full-ID lookup/validation; no truncation may be treated as a provider-native CAS capability. Pagination must bind one snapshot, handle stale cursor fail-closed/restart, and include relevant comments/metadata in observation drift.
- **Full-state updates:** `hn issue revise` replaces the whole IssueState. Preserve unrelated labels, assignees, relations and metadata from the verified single head; do not erase human changes through sparse patch emulation. A preflight read cannot manufacture global write exclusion.
- **Rich mapping:** title/body/criteria/assignees/blocking relations have native slots. Go Kitty’s criteria outcome/verifier/required/evidence hints, design context, write scopes, cross-domain reason and provenance need a documented, versioned metadata representation. Hubnot metadata allows 64 string keys, values ≤4096 bytes; input ≤256 KiB. Reject oversize/unrepresentable records explicitly; no lossy truncation or general-app private convention.
- **Dependencies:** WorkID ↔ full issue-ID bindings belong to Go Kitty metadata/authority observation. Resolve dependency direction (`blocks`: source blocks target) and two-pass create/link without inventing refs or copying external IDs into authoritative WorkIDs.
- **Idempotency:** actor-scoped operation keys replay original facts; changed request returns operation conflict. Stable keys must include project/work/operation and survive restart, while respecting 128 printable-ASCII byte limit. Reconcile ambiguous successful writes with the same signed request; never mint a new key to hide uncertainty.
- **Repository/identity:** use explicit canonical repository and executable paths. Hubnot stores private identity in its Git directory and events in custom refs. Inspect must not run `hn init`, generate keys, alter Git config/hooks, select remote actors or sync. Qualify linked worktrees explicitly: Hubnot `requireGitRepository` uses `--absolute-git-dir`, so per-worktree identity path versus shared refs is a real binding concern. A canonical main checkout as provider workspace is the conservative composition choice.
- **Identity pin:** current `hn version` prints only `0.0.1-dev`, not a JSON source identity. Pin full source commit plus reproducible build tuple and binary SHA-256; the version string alone cannot qualify the candidate. Probe actual strict `hn.issue/1` envelopes.
- **Export/backup:** paged issue export can be provider-portable data, but a Git backup must include accepted actor refs/history and intentional identity recovery policy; ordinary code clone is not automatically a restorable tracker backup. Declare capabilities unsupported until round-trip restoration has been exercised. Do not copy private keys into evidence/artifacts.
