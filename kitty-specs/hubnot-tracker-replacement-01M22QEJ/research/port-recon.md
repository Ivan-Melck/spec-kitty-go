# Go Kitty → Hubnot port reconnaissance

Read-only investigation, 2026-09-09. Go Kitty tracker source is unchanged from `94e7c854`; current checkout advanced to orchestration scaffold `034324e4` during investigation. Hubnot source inspected: `5a0e9cda0639241cfb45d2780e1b50c487109747`. No source/runtime mutations or suites run. The only authored file is this report.

## Recommendation

Replace the Beads adapter through the existing provider-neutral ports, preserving Go Kitty's newer WorkDefinition and durable operation/authority model. Hubnot is sufficient for bounded catalog creation/reading, descriptive assignment, discussion, and graph projection. Do **not** advertise global guarded update, atomic assignment, or safe compensation based on its actor-ref CAS. Retain the same honest unsupported work-definition update behavior Beads currently has until a separately specified stronger provider primitive exists.

The important integration work is deterministic encoding and history-based recovery, not a second adapter database. Add a small public machine-readable actor/operation-observation surface to Hubnot if allowed; it reduces expensive and fragile recovery scans without changing signed event semantics.

## Retry after response loss, without an adapter DB

1. Pin repository binding and a dedicated stable Hubnot signing actor. Actor is part of replay identity; identity rotation/change must fail preflight until deliberately rebound. A Go Kitty operation retry under a different actor is a new Hubnot operation.
2. Derive a bounded operation key from canonical `(version, ProjectID, OperationID, port action)`, e.g. `gk1:<sha256>`. Do not include target WorkID in the key: reusing the operation on another target must be detected. Action is necessary because current portable graph conformance uses the same OperationID for put and remove. Keep the original OperationID and complete semantic digest in signed metadata or the comment envelope.
3. Before any stale-observation/current-state checks, observe prior signed operations for that actor/key. For a found event, verify intended action, mapping, requested semantic fields, original OperationID and digest. More than one result or changed semantics is conflict, never a guessed winner.
4. Recover the **original parents and complete signed request state** from that event. Repeat those exact Hubnot inputs, not a newly merged current-state request. Hubnot binds expected parents and all content in the request digest. It then returns the original event before mutable head guards.
5. Return the replay evidence plus a fresh current observation. If current state has conflicting heads, surface reconciliation instead of inventing a WorkRecord; record the known prior effect even if current observation cannot be cleanly constructed. Do not discard operation success merely because unrelated later edits exist.
6. If no event is found after a complete bounded snapshot scan, compute a fresh request using the caller's expected observation and current preserved foreign fields. On process timeout/response loss, do not blindly retry a recalculated request: re-enter the observation path. Incomplete/stale/resource-limited scans leave outcome ambiguous, not absent.
7. For definition creation with dependencies, creating the issue and editing blocker issues is a multi-event saga. Derive stable child operation keys, recover each child's signed facts, and propagate `PriorMutation` accurately. Go Kitty already has this authority-owned saga distinction; no hidden adapter journal is needed.

The protocol already exposes enough per-issue history (state, parents, operation, actor, intent) to reconstruct known-issue revisions. Lost-create recovery can page list then history for all issues, including conflicted ones. However list gives no mapping/operation fields, history is per issue, and the catalog can change between commands. A complete scan must pin/compare all snapshots, bound total calls/bytes, restart finitely on change, and never treat partial scans as absence.

A concrete conformance trap: `conformance/catalog.go:77` repeats UpdateWork with the **new** observation revision, whereas Hubnot requires original parents for identical replay (`issue_commands.go:597`). Passing the new observed head as `--expect` breaks existing portable behavior. History-based semantic replay fixes this; storing only last-operation in current metadata does not.

## Protocol gaps and minimum remedies

- **Public signer discovery/pinning:** `identity_continuity.go:348,362` exposes human text only; issue mutation responses omit signer, and the command loads mutable active identity. Add `identity show --json` containing only public identity and a mutation `--actor <expected-id>` precondition checked against the identity actually used. This closes identity-change races and avoids reading private key files or parsing prose.
- **Direct durable operation observation:** add a bounded read command for `(actor, operation)` returning original issue/event ID, intent, parents, full state or body, and signed request digest; typed absent/conflict results. Filter during the existing verified reader; no new storage required. A single snapshot-bound lookup simplifies lost-create recovery, duplicate detection, and semantic replay. This is an ergonomic/performance improvement; bounded complete history scans are the current fallback.
- **Representability:** native criteria ≤64, IDs ≤64 bytes, text ≤4096; metadata ≤64 pairs ×4096 bytes and whole payload ≤256 KiB; body/comment ≤64 KiB. Go Kitty accepts a 1 MiB opaque metadata object and substantially larger legacy criteria/discussion inputs. Preflight the complete encoded request (including envelope overhead) and return typed unsupported/invalid-size errors before any child write. Do not truncate or silently drop scope/evidence fields. If production fixtures exceed this subset, introduce a general bounded structured metadata/attachment extension; do not secretly widen Hubnot limits only for Go Kitty.
- **Attribution:** public comment append accepts body/operation, not arbitrary Author. A signed semantic-author envelope is sufficient if explicitly described as an assertion by the bound signer. A generic optional attributed-author field would be cleaner, but must retain actor as cryptographic provenance and bind author into replay semantics.
- **Guard strength:** `capabilities.go:34,193` requires a provider-enforced mutation guard and forbids manufacturing one via read-then-write. Hubnot's snapshot checks plus one actor-ref CAS do not exclude another actor's simultaneous valid edit. No adapter lock or extra metadata can fix that. Keep GuardedUpdate=false and compensation unsupported; a stronger mode requires a separately qualified authority/serialization primitive or a new explicitly weaker port capability, not relabeling current semantics.
- **Graph saga and mixed state:** source-blocker storage makes dependency installation/removal touch other issues. Refuse conflicts/cycles and verify graph facts after each step. Creating an issue with dependency metadata alone is not success; `ObserveDefinition` must cross-check required actual edges. Do not claim atomic complete-definition replacement across these writes.

## Honest initial capabilities

`CatalogRead=supported`, `CatalogCreate=supported` for representable values, `CatalogUpdate=unguarded` with native stale-head preflight; `BlockingGraph=supported` after graph saga qualification; `Discussion=observably_idempotent` only after pinned actor and attribution/replay tests pass (otherwise append_only); `Assignment=unguarded`; `ObservationRevision=content_derived`; `SafeCompensation=unsupported`.

Use `ConcurrentWriters=none` as the conservative declaration under the current port vocabulary: actor-local CAS does not serialize provider mutations across actors. If adapter serialization is added, explicitly state its scope and do not turn it into a global guarantee. `PortableExport` and `RestorableBackup` stay unsupported until actual archive/restore contracts and key/trust/repository restoration tests qualify them. Git availability alone is not backup qualification.

`WorkDefinitionCapabilities{Create:true, GuardedUpdate:false, BlockingGraph:true}` preserves the current Beads capability ceiling (`beads/catalog.go:173,263`). The decomposition service already derives requirements per proposal; do not weaken that gate to admit an unsupported update (`mission/decomposition.go:188`). Preserve existing GapDB execution/operation authority and mission result verification.

## Focused implementation acceptance targets

Use existing portable conformance plus actual Hubnot subprocess/Git histories: complete rich definition round-trip; unmapped/duplicate/rewritten mapping refusal; native criteria versus metadata drift; unknown metadata preservation; dependency direction and partial-saga recovery; author/body exactness; replay after response loss and later edits; new expected observation on same portable operation; changed signer; concurrent actors; conflicting/cyclic paginated histories; all size failures before mutation; and refusal of atomic assignment/guarded compensation. Add complete-snapshot scan interruption tests if the direct operation lookup is deferred.

## Canonical M3 boundary: preserve both validation paths

`WorkDefinitionCapabilities.Validate()` (`work_definition.go:330`) requires all three capabilities and must remain unchanged. Hubnot's honest `{Create:true, GuardedUpdate:false, BlockingGraph:true}` must continue to fail full-port/M3 qualification. Beads already declares exactly that partial set; this replacement must not claim to complete M3.

There is a separate, intentional useful path: `DecompositionService` calls `capability.Require(decompositionRequirements(command.Work))` (`mission/decomposition.go:166,260`). Creation needs Create; dependency-bearing proposals also need BlockingGraph; any existing-item update requires GuardedUpdate. This check runs before durable operation reservation and provider mutations. Therefore bounded create-only decomposition and subsequent ObserveDefinition/ReadWork can work today without any kernel/capability relaxation. Retain authority-owned plan approval, quality validation, reservation, attribution and final workgraph checks unchanged.

`UpdateDefinition` should return `ErrorGuardedUpdateUnsupported` without mutation. Generic `UpdateWork` must also refuse a record containing complete-definition metadata, matching `beads/catalog.go:350`; otherwise the legacy unguarded port becomes a bypass around the complete-definition contract. It may update simple catalog-only records when callers explicitly request `UpdateUnguarded`, preserving foreign fields and reporting cross-actor conflicts honestly. Read-only observation of human-edited Hubnot state remains possible; observation does not approve new decomposition or authorize execution.

M3 work left outside this replacement: a provider primitive and qualification that can enforce the complete work-definition update contract, including expected observation and any required multi-issue graph consistency, or an explicitly redesigned weaker planning contract reviewed as its own architectural change. Do not weaken `Validate`, substitute a fake provider, infer authority from Hubnot status, or label actor-local CAS as completion of that work.
