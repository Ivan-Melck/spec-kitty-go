# WP07 preservation scope bridge — independent recommendation

**Recommend a fixed hosted selection plus a mandatory local transition receipt.** Keep the full mission census strict. Do not make absent local data pass by validating an old receipt under the same claim.

The current family10 conflates two observations: immutable tracked history reproducible from source, and the continued existence/content of nineteen ignored files and private historical refs/stashes in the original repository. A fresh clone cannot observe the latter. An uploaded digest-only receipt can establish that a prior local verifier made a claim; it cannot establish current local bytes or become fresh hosted attestation.

Minimal amendment:

1. Split `cutover.preservation` into closed concrete rows `cutover.frozen-source` and `cutover.local-recovery`. The first checks the829 pinned tracked paths/objects/modes and frozen evidence identities from the candidate source in both scopes. The second explicitly reads the original repository and compares the exact19-file baseline and original historical ref/stash census; it is mandatory for full local mission acceptance. Missing originals, manifests or rows remain non-admissible for that full scope.
2. Add one named fixed `hosted-provider` selection in the same canonical manifest/selection mechanism already planned for identity. Its exact required IDs include every repeatable public/compiled/provider/active-cutover/frozen-source scenario; they exclude only the expressly local-recovery row. Freeze that selection independently of discovery/results. No environment-driven auto-selection, skip, zero-file pass or arbitrary row filtering.
3. Give hosted artifacts explicit scope/selection identity and exact selected expected/start/terminal/pass census. They may be valid/admissible for that selected scope, but must remain non-full and must never satisfy the full local validator. Carry the excluded local obligation as an explicit boundary, not a passed or skipped selected row. Hosted CI must use the corresponding fixed selected wrapper/validator; it must not call a full wrapper and teach it to ignore one failure.
4. Local WP10/acceptance joins the source-bound hosted result (if available) with the required byte-checked local transition proof for the same final candidate/source tree. Recheck the original19 and refs after final integration/merge as already planned. Keep private data and private refs local; a public summary, if desired, identifies only the evidence scope, source and bounded result. No database upload or remote assertion about local current content.

Proposed qualification wording: “The full mission qualification census requires every scenario, including local-recovery byte/ref checks against the original repository. Hosted provider qualification uses the named fixed hosted-provider selection; it is admissible only for that selection and is not full mission acceptance. Frozen tracked evidence is checked in both scopes. Missing selected prerequisites or rows are non-admissible. Absence of local original data never selects a scope or proves preservation.”

This is an evidence-mode clarification of existing FR-011/SC-003/C-004, not a new product capability or relaxation of the local preservation requirement. WP07 owns the manifest/selection/receipt validator and qualifier; WP09 owns campaign/CI wrapper selection and current documentation; final acceptance/root already owns local preservation verification. No new ownership or DAG edge is necessary. Prefer a clearly named hosted wrapper if the existing full wrapper’s name/contract promises full execution; keep exact identity selection separate.

Evidence inspected: current qualification.md family10 and no-omission rules; WP07 final-consumer plan's full/selected validator distinction; WP09 active-vs-historical validator ownership; frozen Phase3 profile validator in mission_method.go (closed historical counts/digests independent of current registry); BeadsEvidenceProof's explicit expected/started/terminal and missing-prerequisite guards. The external verify-go-historical-preservation.py already checks829 committed and working objects/modes separately from19 original files and original branch/stash identities, using three pinned manifests. Its preflight baseline explicitly says it is not final acceptance. Preserve that distinction rather than replacing actual local comparison with a source receipt hash.
