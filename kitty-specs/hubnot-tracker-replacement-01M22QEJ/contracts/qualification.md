# Qualification contract

One active Hubnot manifest owns exact accepted source/toolchain/target/build recipe/binary digest and closed required scenario census. Installer, runner, validators and selectors derive or verify identical values. Dev version alone never admits. Source includes independently accepted prerequisite; older PR #2 source is insufficient.

Build externally with pinned Go 1.26.7 and deterministic recipe. Verify source before build, bytes before execution. No mutable-branch/PATH fallback. Missing prerequisites, skipped tests, empty selectors and omitted scenarios are non-admissible. Record exact commands/source tree/binary/environment/exits and individual results.

The canonical installer is the externally built qualifier's `install --go-bin ABS --source CLEAN_ACCEPTED_CHECKOUT --destination ABS` subcommand. Build that executable with the pinned external recipe already required for qualification. It preserves exact source/toolchain/binary admission and refuses unrelated existing destination bytes. Retire the redundant shell bootstrap instead of adding a second launcher or weakening executable analysis. No compiler-basename restriction applies to this compiled API. Current Make, CI and documentation must invoke the compiled installer and record its actual exit and identity receipt.

Record evidence modes explicitly. Public duplicate-key/divergent-intent attempts must prove refusal, unchanged refs and a unique original; do not label them as an injected history containing two accepted records. Source-bound unit boundary adversity separately exercises duplicate/incomplete original lookup responses with exact test IDs and exits, as permitted by WP07. Both are required evidence. An impossible public malformed-history fixture is not grounds for signed-ref fabrication or substituting unit calls for delivered positive consumer workflows. Publicly prepared persisted-partial saga/pair fixtures likewise identify the effects actually retained and recovered, without claiming an in-flight crash.

Preservation has two closed rows: `cutover.frozen-source` checks the pinned tracked historical objects, modes and evidence identities; `cutover.local-recovery` compares the actual original repository's nineteen files and historical branch/stash identities with their recorded baselines. Full local mission qualification requires both rows and every other required scenario. Missing originals or baselines are non-admissible for that full scope, never an empty-data success.

Hosted provider checks use the named fixed `hosted-provider` selection. Its independently defined census includes every repeatable scenario and excludes only `cutover.local-recovery`; frozen tracked evidence is checked in both scopes. Hosted evidence records its selection identity, exact selected expected/started/terminal/passed census, selected-scope admissibility and explicit non-full status. It cannot satisfy the full local validator. Missing selected prerequisites or rows remain non-admissible. Absence of local data never selects a scope or proves preservation. Final local acceptance and post-integration verification still read the original files and recovery refs; a receipt hash or hosted result cannot replace those observations.

Playback evidence uses the actual production reducer composition through RunV2, checkpoint-plus-suffix equivalence and typed projection assertions, together with the existing structural no-I/O guard. Tracker dispatch uses its separately connectable HostFactory tripwire. Pure playback has no provider port; an unused panic object is not an observed zero-call test, and arbitrary caller-supplied reducer closures are outside the structural guard claim. No provider dependency or sidecar startup is introduced solely for this witness.
