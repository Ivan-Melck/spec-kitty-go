# WP01 review cycle 3 — mini-local

Verdict: **REJECT**

Candidate: `c8a7e57656883fda0acfd7a12f61a73d6e594ebc`

## Blocking findings

1. **HIGH — The forward migration does not upgrade the schema actually shipped by the prior WP commit.** `internal/controlstore/sqlite/migrations.go:98-125` treats `user_version=1` as the newly rewritten `migrations[0]`, while commit `70e6005` already emitted a different version-1 schema (`operations` had `result_token` and no `correlation_id`; `leases` had `token`, not `token_digest`). The new test at `internal/controlstore/sqlite/authority_test.go:277-309` creates its upgrade fixture from the *new* `migrations[0]`, so it cannot detect this incompatibility. Exact-commit adversarial proof created databases with `70e6005` and opened them with `c8a7e57`: a used database failed `Open` with `control-store token key is missing for a database containing authority state`; an empty old database opened but its first new claim failed `no such column: correlation_id`. Add a real old-v1-to-v2 migration for columns, token state, constraints, and replay; test against a fixture generated by the prior implementation, both empty and with a durable successful operation.

2. **HIGH — Heartbeat and expiry still violate the common command/diagnostic envelope.** `internal/execution/model.go:160-188` gives `HeartbeatRequest` and `ExpireRequest` no schema version, correlation ID, OperationID, ActorID, or ProcessID. Consequently the early-expiry diagnostic at `internal/controlstore/sqlite/authority.go:291-296` and stale diagnostic at `:309-316` leave `CorrelationID` and `OperationID` empty. Isolated black-box tests exercised a wrong-token heartbeat and early expiry and rejected both envelopes as incomplete. Extend the requests and store boundary so all refusals, including validation and busy paths, contain every NFR-006 field from the originating command.

3. **HIGH — FR-019 durable-boundary/lost-response recovery remains unproved.** The only hook invocation is `SR-00` before the transaction at `internal/execution/lease.go:70`. There is no `SR-02` hook after run/lease commit and before helper response. `TestWP01LostResponseReplay` at `internal/scenario/claim_race_test.go:52-79` receives and inspects the first successful response; it never drops the response or crashes after commit, so the named test does not prove recovery from the durable ambiguity it claims. Add the post-commit/pre-response boundary and use a real helper crash/drop to prove the same OperationID replays the committed capsule and token without duplicate state.

4. **MEDIUM — The constrained seed API silently accepts conflicting immutable identity.** `internal/controlstore/sqlite/authority.go:46-53` uses `INSERT OR IGNORE` for projects, revisions, and work and never checks whether an ignored existing WorkRevision belongs to the requested project/mission. An isolated test seeded one identity, then reseeded the same revision/work with a different project/mission; `SeedAuthority` returned success. Use conflict-aware insert/readback checks and return a typed immutable-identity conflict instead of false success.

5. **MEDIUM — Concurrent first-open can fail in token-key creation and startup locking.** `internal/controlstore/sqlite/db.go:66-104` performs read-then-`O_EXCL` key creation without handling a concurrent winner by reopening the completed file. A 16-caller first-open adversarial test repeated 20 times produced both `create control-store token key: ... file exists` and `ping control database: ... SQLITE_BUSY`. Make first initialization converge under concurrent callers and translate bounded startup contention consistently; add independent-process coverage.
