# WP03 Dependency Blocker 1

WP03 stopped before source edits because the approved WP02 sealed-plan API was
not persistence-complete. In particular, it lacked canonical capability-head
values, complete effect and eligibility records, checkpoint-slot transitions,
and conditions attributable to every mutable member.

Building around this in WP03 would violate the package's explicit prohibition
on parsing the plan evidence serialization, inventing canonical values, or
maintaining a second membership model. WP03 returns to planned until the
bounded WP02 correction in `post-approval-defect-1.md` is independently
approved. Its lane contains no WP03 production edits and may then be refreshed
from the corrected dependency normally.
